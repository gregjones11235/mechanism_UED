## The five problems and their resolution

### 1. Long-episode policy-version provenance (§二) — FIXED
`RMTTrajectory` / `RMTReplaySample` now carry `policy_version_start` / `policy_version_end` /
`policy_version_span`. At episode completion (`rmt_collect.collect_rollout_rmt`) the START
version is read from `pending.policy_version[e]` **before** `reset_slot` overwrites it; END is
the current accepted `policy_version`; span = end − start with `assert end >= start` and
`assert span >= 0`. `policy_version_at_collection` is kept as
**DEPRECATED_ALIAS_OF_POLICY_VERSION_START** (it is no longer the end/current version — that was
the bug). `reset_slot(e, policy_version=current)` semantics are KEPT: the new episode's remaining
steps in the current rollout are still generated by the current rollout policy, and the PPO
update happens only after the rollout, so the new episode's start version is the current version.

Scientific boundary: `PER_TRANSITION_POLICY_VERSION=NOT_RECORDED`,
`EPISODE_POLICY_VERSION_RANGE=RECORDED`. V-trace off-policy correction uses each transition's
STORED behavior `log_probs` — it does not require per-transition policy versions.

### 2. `max_policy_lag=16` declared but unused (§三) — FIXED
For `original_vtrace` the policy-lag gate is **NOT_APPLICABLE**: the configs' active
`max_policy_lag: 16` was replaced by
`policy_lag: {active: false, mode: not_applicable_original_vtrace, max_policy_lag: null,
correction: {method: vtrace_importance_sampling, rho_bar: 1.0, c_bar: 1.0}}`.
`replay_mode=original_vtrace` + `policy_lag.active=true` (or a stray top-level `max_policy_lag`)
fails closed with `ORIGINAL_VTRACE_POLICY_LAG_CONFIG_CONFLICT` (config validator + a runtime
guard in the launcher). The legacy lag gate lives ONLY under `legacy_full_p2_only.max_policy_lag:
16` (default-forbidden mode). Checkpoint/summary/run manifest now record
`policy_lag_gate_active=false`, `max_policy_lag=null`, `off_policy_correction=
vtrace_importance_sampling`, `rho_bar=c_bar=1.0` (legacy would record `active=true` + `max_policy_lag`).
