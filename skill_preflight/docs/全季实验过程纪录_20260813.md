## 阶段一 · 立项与减法(约 7/5 – 7/8)

**起点问题**:DiCode(ICML 2026)证明了 235B 教师能驱动 code-level UED。把教师换成**单卡本地 14B**,管线按同行的 scaling 消融应该直接崩——那么加什么机制能不崩、能救回多少?

**第一次 baseline 报废**:`DiCode-run-1783387797` 跑了约 6 小时,事后诊断出两个致命 bug——`global_env_steps` 在 session 4 冻结(课程随之冻结,archive 卡在 16 个节点、新任务停止进入)、embeddings 从 session 1 起持续 404。**这一炉不能当对照,必须重跑。**

**方案减法(本季第一个关键决定)**:原设计有四个机制(skill graph、小模型生成、preflight gate、generate-then-edit 编辑器、微训探针、hold buffer)。砍成**一条三步流水线**:

> Skill Graph 定位最浅的未掌握 tier → 小模型生成候选关卡 → preflight learnability gate 判可学/太难/太易 → accept 进 archive

编辑器、L4 微训探针、复杂 hold buffer 全部降级为 future work。**连带收益:消融从"拆四个机制"变成干净三组**(baseline / +A / +A+B)。

**分工确认**:v5 设计是队友刷 SOTA 那条线的,本线不切过去,守住"小模型高效方案"的分工。

**架构发现**:DiCode 的生成+编译跑在 `executor.submit(...)` 后台线程里,而 preflight 需要 `rl_train_state` ⇒ 两个 hook 都必须放主循环——★A(skill graph)在 Step 2 派发 evolution worker 之前,★B(preflight)在 Step 3 拿到 `new_task_ids` 之后、与 archive 采样合并之前。

## 阶段二 · 基础设施战役与干净 baseline(约 7/8 – 7/11)

这一段几乎全是工程,但它决定了后面所有实验的可信度。

| 问题 | 根因 | 修法 | 效果 |
|---|---|---|---|
| **14B 生成龟速 0.36 t/s** | Ollama 在 JAX 占满显存**之后**加载,33/49 层留在 CPU | max_tokens 32768→8192(KV cache 6G→1.5G)、XLA 0.85→0.75、**先起 Ollama 预热再启 JAX** | **69.8 t/s,提速 ~194×** |
| 生成侧挂起拖死训练 | worker 同步无超时 | `worker_sync_timeout_s` 熔断,生成挂了 RL 继续用现有 archive | 全程零 500、零 "No new tasks" |
| 14B 输出带 ```python 围栏 | 小模型泄漏 markdown | R1 fence-strip 补丁 | **SyntaxError 从有到 0** |
| 换 pod 后 venv 丢失 | venv 建在容器临时盘 | 迁到网络卷 `/workspace/venv` | 换 pod 只需 source |

**方法动机的第一手证据**(这条后来一直在用):校验阶段真跑生成代码,全 run 错误分布 = **AttributeError 15 次**(如 `Achievement.DESCEND` —— 幻觉出 Craftax 里不存在的成就枚举)、TypeError 10 次、**SyntaxError 0 次**。小模型的典型失败**不是语法,是语义幻觉**——这正是 skill-graph(引导方向)与 preflight(过滤无效)要缓解的东西。

**守夜抓到的第一个静默失败**:开跑一小时内发现"+A+B"其实只有 +A —— preflight 抛异常被 `try/except` 静默降级。教训写进规矩:**验证阶段宁可崩溃,不要静默降级**。

**干净性四项检查**(此后每臂沿用):课程单调增长 / 零致命故障 / hook 状态与声明一致 / embeddings 全 200。

## 阶段四 · 学生侧干预与崩溃季(约 7/20 – 7/31)

**先做验尸,再做干预。** 1024 条 per-episode 记录的解剖给出三个病理:**76% 死在 dungeon 一层**、到达 gnomish 二层的 **91% 溜溜球退回**、时钟截断吃掉最高分的尾部。

三个 reward 干预,**全部离线零**:
- φ-depth potential shaping(Ng-safe,c=0.5)
- CombatBountyWrapper(深层首杀 +2.0,故意非势函数)
- **placebo**:非战斗稀有成就 +2.0,同量级、索引集不相交 —— 连自己重赏的成就都没抬起来

⇒ 联合裁决:**激励不是约束,勇夫缺的不是赏,是梯子。**

**两个基础设施 bug,都是从"曲线太平"看出来的**:
1. **step_env bypass**:`DistributedMultiTaskOptimisticLogWrapper` vmap 的是 `_env.step_env` 而不是 `step`,只覆写 `step` 的 wrapper 被静默绕过 —— 前一炉 bounty 是哑弹;
2. **在线 eval 泄漏(结构性)**:循环内 `evaluation/mean_return` 取自训练 env 的 `original_craftax` 槽位,不是真 held-out。账目分毫吻合:在线−离线 ≈ +3.4 = 2.0×(orcSoldier 0.86 + orcMage 0.73)。**修法**:每 session 真跑 `run_session_evaluation`,训练槽位改名 `evaluation_shaped/*`。

**崩溃卷宗与测定台**:同位 total step ~15500 七次复现;四臂测定台 S(自适应值缩放)/ F(critic 梯度防火墙)/ C(LR anneal 钳制)/ L(从 ckpt 6900 强制 lr=2e-5)**系统性证伪三个因果理论**,第四个(resume 时 optimizer reset 导致全速 LR 超车)由 L 臂续跑验证 → 沉淀成附录里的 **fork/resume LR 法条**。

**7/21** SIL 设计卡定稿(片段级 BC、w=(R−V)⁺ 带上限、burn-in 整窗 + burn-in=0 消融针、预注册判据与止损线不设在总分)。**7/24** RA meeting。

## 阶段五 · 全预算主线与五机制记分牌(约 7/26 – 8/4)

**longStack(seed 1)于 7/25 19:37 点火**,成为本项目第一个自然跑到 2e9 的臂(在此之前整季只有 s1–30 与 s155–172 的数据,中间 85% 是空白),官方分 **44.73**(last-10);wandb `8tlg55ky`,墙钟 63.4 h。

五个预注册机制全部执行完毕,**全部失败**:

| 机制 | 判决 |
|---|---|
| SIL(早窗保持) | **−1.10,p≈0.03**;反向分支生效 |
| 晚窗注入 ladder | 教学路线两头堵死;但探针产出**墙定位**:落差唯一在 R0↔R1(−25pp,木镐),六次开小灶填不平 → **scaffold 依赖新发现** |
| slots=9 | null-to-negative(带星:resume 重置计数器与 LR) |
| r3_v2 + tier_cap | **回退 −4~6**;起点夹在 s12–24 = grant 起窗 |
| batch_backfill | null + 机制闭合(批缺口是早窗病,成熟期池富但批不缺) |

**失败里长出两个真发现**:scaffold 依赖(任务级 scaffolding 的成功指标 SR↑/ep_len↓ 与课程级结果**反相关**)与深度墙。

**7/31 夜事故**:MooseFS FUSE 渐进劣化,batchFill(~00:32)与 stackRep(~01:55)先后 core dump;共因,与补丁无关(无补丁复刻臂同死)。教训:守望脚本 kill 走 pgrep PID,勿用自匹配 `pkill -f`。

**8/4**:seed 2/3 收官 → 三种子 **44.01±0.79**;三种子两两差均值 1.05 ≈ 预先实测的种子地板 1.13(**带宽预测在全预算兑现**)。同日核完公开谱系对照表。
