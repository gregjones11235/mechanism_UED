# 勘误注记:ff6b956 "ROOT CAUSE" 措辞修正

> 2026-07-20。关联 commit:ff6b956(clamp,装错路径)、5b650f3(真修复)。

## 勘误内容

ff6b956 的 commit message 及代码注释将 "LR 退火转负" 判定为崩溃 "ROOT CAUSE";
其后 crashfix_C 臂照崩,曾使该理论被预注册判据"证伪"。两者均需修正:

**理论本身是对的;修复装错了代码路径。** ff6b956 的 clamp 只写入
`ppo_tr.py` 的 schedule,而 resume/fork 链路的 TrainState 由
`load_weights_only`(`train_state_utils.py`)用其**自有的无 clamp schedule**
构建 tx——flax TrainState 的 tx 随状态走,`ppo_tr.py` 中的 clamp 对一切
续跑段不可达。因此 "clamp 后 C 臂照崩 → 理论证伪" 不成立:**理论从未被
真正测试过**。

## 定案证据(零 GPU)

1. **restore 日志**:全部 run(含七个崩溃 run)的 optimizer 计数恢复正确
   (恒等于 全局 update 位 × 32),`Optimizer Reset` 兜底打印从未触发——
   排除计数归零类机制(第四理论 "Optimizer Reset 满 LR 超速" 据此按机制
   错误注销;其 crashfix_L2 单变量对照数据保留,重新归档为 "LR 因果性
   证据");
2. **算术判决**:TOTAL_GLOBAL_UPDATES = 15300(2e9 预算,session 上取整),
   min_lr = 2e-6。无 clamp 时 LR 过零位 = TOTAL × (1 + min_lr/(lr−min_lr)):
   - lr = 2e-4 → **idx 15454**:placebo / S / F / A 臂均死于总 15400-15500 ✓
   - C 臂分叉于 count 15400(过零前 54 步)→ "+150 即死" ✓(无需"权重
     旧伤"假设)
   - lr = 2e-5 → **idx 17000**:crashfix_L2 整个观测窗(≤15800)LR 仍为正,
     故全程健康 ✓(其存活曾被误读为"满 LR 超速定罪"——判据判别力盲点)
3. **复活实验**(smoketest_clamp):从 C/S/F 同源 ckpt(count 492800,
   修复前三具尸体验证过的必死局)fork,`LR at restored count = 2.000e-06`,
   过界 2 个 session 健康(mean_return 43.35 / 43.17)。
