## 1. 根因(craftax 1.4.5 game_logic.py l.144-152,源码实锤)

宝箱掉落存在**楼层门控**:书 = **3/4 层(sewers/vault)首箱专属**;弓 = 1 层首箱;
宝石/药水/资源 = 纯概率无楼层条件。前置图的 `learn_fireball/learn_iceball ← {open_chest}`
漏了楼层条件,真边 = `{open_chest, enter_sewers}`。**手工图与自动抽取 spike 双双漏检**
(E1 只抽掉落字段、未解析掉落行的 player_level 门)。

## 2. 因果链(解释 run 的全部异常,无残留谜团)

1. open_chest 62%→80% ≥ 0.3 → 调度器自 ~session 28(~200M)判 learn_* "前置齐" → 入池;
2. 真前置 enter_sewers = 0 → learn_* 任务在 held-out 上结构性不可学 → 800M 步绝对零;
3. **目标池 6 席被毒 2 席**,真前沿(下楼链 gnomish→sewers)火力被稀释;
4. mean_return 平台 = iron 族到自然带(30-45 震荡,非遗忘:无持续下行,collect_iron 稳 65-70)
   + 下一族(下楼链)供给不足;
5. 与"灾难性遗忘"假说的鉴别:宝石线在涨、iron_armour(钉子户)在涨、defeat_orc 在涨
   (= 1 层清怪进度在走)—— 系统活着,只是火力错配。

## 4. 运行决策:kill → pull → **resume**(不重跑,不放弃)

理由:调度器每 session 从 eval metrics 现算目标 → 修好的图在 resume 后**首个 session 即生效**,
剩余 ~950M 步获得干净目标池,火力全部集中在下楼链。相比:跑完毒池 2e9 = 浪费一半预算;
从零重跑 = 60h + 钱,且丢掉一个天然实验(火力重定向后下楼链是否打开 = 机制有效性的又一证据)。

**论文口径(诚实记录)**:该 run 定性为 "2e9 with a curriculum-graph hotfix at 1.05B"
——中途干预必须写明;hotfix 前后的 targets 分布与 enter 族曲线对比本身是有分析价值的
自然实验。若最终冲线成功且预算允许,可与 PI 讨论干净复跑一次作 confirmation。
