## 崩溃案卷宗(已破・已修・已验,2026-07-20 结案)

死状:value_loss→1.5e10、grad→2.5e10、熵→0、ret −0.90 躺平;七个 run
死于总 15300-15500(A/placebo/S/F/bounty 系)或分叉即死(C)。

**真因**:resume 链路使用 `load_weights_only`(train_state_utils.py)中
无 clamp 的 anneal schedule;全局 update 计数越过 horizon(TOTAL=15300)
后 frac 转负,LR 于 idx = TOTAL×(1+min_lr/(lr−min_lr)) 过零(2e-4 臂 =
15454,2e-5 臂 = 17000),Adam 变梯度上升,策略被主动摧毁。崩位为
**全局位置锁定**,"分叉 +1800" 系多数 fork 起点恰为 13700 的巧合;
C 臂分叉于 count 15400(过零前 54 步)故 +150 即死,无需"权重旧伤"假设。

**侦破线**:三理论证伪(其中理论一的"证伪"后被判无效——ff6b956 的
clamp 装在 resume 不可达的 ppo_tr.py,详见 勘误_ff6b956.md)→ 第四理论
(Optimizer Reset)经 crashfix_L2 单变量对照获 "LR 因果" 证据,但 restore
日志证明所有 run 计数恢复正确(全局×32)、从未归零,按机制错误注销 →
理论一复活修正案经算术判决五点全中 + 复活实验定案(smoketest_clamp:
从 count 492800 必死起点 fork,LR 钉死 2.000e-06,过界 2 session 健康
43.35/43.17)。全程零额外 GPU 侦破成本(烟测 ~40 分钟除外)。

**修复**:commit **5b650f3**(`load_weights_only` schedule 补 clamp,
horizon 内逐位一致)。**注意:5b650f3 目前只在 pod 本地,需 format-patch
→ Windows git am → push 走完同步。**

**iron 附案**:L 臂延跑 400 update(总 15500-15800)四条 iron skill 全平、
总分 42.5-43.2 微降——**43.5 为收敛平台而非截断,"重开续跑"提案撤销**。
A 臂尸体(15500 处 iron 全 0)在对照表中自现,与过零位 15454 吻合。
